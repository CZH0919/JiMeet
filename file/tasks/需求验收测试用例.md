本附文按需求稿 1.5 的约定独立维护，逐条给出可执行验收用例。用例编号 `AT-<FR 编号>-<序号>`；参数取值以《修订说明与待确认事项》为准；错误码以 `backend/design_file/api.md` 为准。标注 **【阶段 x】** 表示该用例在 Sprint2 对应阶段验收；未标注的按整体交付验收。执行时仅使用合成身份、测试密码与虚构简历。

## FR-01 邮箱账号注册与登录【阶段 2】

| 编号 | 前置 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| AT-01-01 | 无账号 | 以 `a@tongji.edu.cn`、合规密码、姓名注册 | 201 建立普通账号与会话；`is_admin=false`、`privacy_consented=false`；返回本人资料 |
| AT-01-02 | 无账号 | 分别以 `a@tongji.edu.cn.evil.com`、`a@evil-tongji.edu.cn` 注册 | 400 `VALIDATION_ERROR`，不建账号 |
| AT-01-03 | 无账号 | 以 ` A@Tongji.Edu.Cn ` 注册并规范化为小写邮箱后，再以 `a@tongji.edu.cn` 注册 | 第二次 400（details.email 已注册），已有账号密码、绑定、权限不被覆盖 |
| AT-01-04 | 无账号 | 并发发起两个相同邮箱注册（并发测试） | 仅产生一个账号；失败方得到 400，不产生半成品账号 |
| AT-01-05 | 无账号 | 分别提交 7/129 位密码、纯数字密码、常见弱密码、与邮箱或姓名相似的密码 | 均 400，指出密码不合规，不建账号 |
| AT-01-06 | 无账号 | 注册体中提交 `is_admin=true`、`is_staff=true` 或未知字段 | 400；即使字段被识别也不得授予权限 |
| AT-01-07 | 无 CSRF 凭据 | 匿名直接 POST 注册/登录（不带 CSRF 令牌） | 403，CSRF 校验失败 |
| AT-01-08 | 已有账号 | 登录：不存在邮箱；存在但错误密码；不可用密码 | 三种情况均 401 `AUTH_FAILED`，提示一致，不泄露账号是否存在 |
| AT-01-09 | 账号已停用 | 以正确密码登录 | 403 `FORBIDDEN`；会话不建立 |
| AT-01-10 | 已有账号 | 正确邮箱密码登录 | 200 建立会话并轮换 CSRF；`GET /me` 返回本人资料；登出后原会话访问 `/me` 得 401 |
| AT-01-11 | 已取得 CSRF | 注册、登录分别以同一邮箱连续失败 5 次（含字段、密码策略及凭据失败）后再请求 | 各操作第 6 次起 429；每次失败只计一次；邮箱不可解析时仅按 IP 计数，IP 第 21 次起受限；换 IP 不解除邮箱限制，换邮箱不解除 IP 限制；600 秒窗口滑过后恢复 |
| AT-01-12 | 失败次数未达阈值，或限流窗口已恢复 | 以正确密码登录成功后再次失败登录 | 成功清除该邮箱键计数，之后重新累计；限流仍生效时正确密码也返回 429 |
| AT-01-13 | 已有账号 | 登录/注册响应与 `/me` 响应检查 | 不返回密码、密码摘要、`real_id`、`sso_subject` 等内部标识 |
| AT-01-14 | 无账号 | 注册响应校验 | 不包含“已验证邮箱归属/师生实名”含义的字段或文案；`name`、`role` 原样保存为展示信息 |
| AT-01-15 | 历史无可用密码账号 | 以受控命令初始化并登录；重复初始化、超长及相似密码、并发初始化 | 合规初始化后可登录；已有密码不被覆盖；无效密码不写入；并发仅一次成功；无公开重置入口，终端输入不回显、管道密码不输出 |
| AT-01-16 | 开发配置 | `ALLOW_DEV_LOGIN` 关闭后调用开发登录 | 404；注册登录主链路不受影响 |
