## 二、已确认设计决策（工程参数）

### 2.1 注册与登录（FR-01，阶段 2 实施）

| 参数 | 取值 |
| --- | --- |
| 邮箱规范化 | 去除首尾空白并转小写后存储与比对；长度 ≤254；域名须精确等于 `tongji.edu.cn`（大小写不敏感），相似域名、附加后缀均拒绝 |
| 密码策略 | 复用 Django 密码验证器：非相似（与邮箱、姓名等属性相似度校验）、最短 8 字符、非常见弱密码、非纯数字；输入长度 8～128 字符；哈希与会话复用 Django 机制 |
| 展示姓名 `name` | 必填，去首尾空白后 1～32 字，仅作未核验展示信息 |
| 昵称 `nickname` | 可选，1～32 字；缺省由服务端生成 `同学_` + 随机字符，不使用真实姓名 |
| 身份标签 `role` | 可选，`student`（默认）或 `teacher`，仅作展示与称谓 |
| 内部兼容标识 | `real_id` 由服务端生成（`reg_` + 随机十六进制），客户端不可指定；不从邮箱前缀推导 |
| 失败限流 | 数据库计数（并发一致，键为 SHA-256 摘要，不存明文邮箱）；窗口 600 秒；阈值：同一邮箱键 5 次、同一来源 IP 键 20 次；超限返回 `429 RATE_LIMITED`，窗口滑过后自动恢复；登录成功清除该邮箱键计数 |
| 错误口径 | 登录失败（不存在邮箱 / 错误密码 / 不可用密码）统一返回 `401 AUTH_FAILED`，不泄露账号是否存在；凭据正确但账号停用返回 `403 FORBIDDEN`；注册遇已存在邮箱（含并发与大小写变体）返回 `400 VALIDATION_ERROR`（details.email），不覆盖已有账号 |
| 会话与 CSRF | 注册、登录成功均建立会话并轮换会话键与 CSRF 令牌；匿名注册/登录同样强制 CSRF 校验；登出后原会话失效 |
| 返回资料 | 仅返回本人资料（uid、昵称、姓名、role、is_admin、邮箱、邮件偏好、隐私确认状态），不返回密码摘要或内部认证标识 |

### 2.2 管理员配置（FR-02，阶段 2 实施）

| 参数 | 取值 |
| --- | --- |
| 授予/撤销 | 受控管理命令 `grant_admin`、`revoke_admin`（按邮箱定位账号，操作写审计）；不提供任何在线授予入口，注册请求不得携带管理员标记 |
| 历史账号初始化 | 管理命令 `init_password` 从标准输入读取新密码（不经命令行参数），为无可用密码的历史账号初始化；不提供“仅凭邮箱重设密码”的公开入口 |
| 撤权生效 | 权限按请求实时读取 `is_admin`；撤销后既有会话的后续公告管理与治理请求同样被拒；本人招聘、申请与个人数据访问保持普通用户规则 |
| 开发登录 | 保留 `POST /auth/dev-login`，受 `DEBUG` 与 `ALLOW_DEV_LOGIN` 双开关控制；非开发配置禁用；正式验收不得以开发登录替代注册登录 |

### 2.3 公告（FR-09，阶段 3 实施）

| 参数 | 取值 |
| --- | --- |
| 标题 `title` | 必填，去首尾空白后 1～100 字 |
| 正文 `content` | 必填，纯文本（不解释为 HTML），去首尾空白后 1～5000 字 |
| 时间类型 `time_kind` | 必填，`deadline`（报名截止时间）或 `event`（活动时间） |
| 时间 `event_at` | 必填，带时区 ISO 8601；不限制必须晚于当前时间；已过时间不自动等于已删除，编辑不因历史时间被拒绝 |
| 相关链接 `link_url` | 可选，最多 500 字，仅允许 `http://` 或 `https://` 绝对地址 |
| 关联招募 `recruitment_id` | 可选正整数；写入时须存在且未删除；关联招募此后被删除/关闭/满员不影响公告保留，详情以 `recruitment_available` 表达链接可用性 |
| 置顶 `is_pinned` | 数据库保留字段，本轮 HTTP 不提供置顶能力：不可写、不参与排序与筛选 |
| 删除原因 `reason` | 治理删除必填，去首尾空白后 1～500 字；本人删除不需要原因 |
| 列表排序 | `created_at DESC, id DESC` 稳定分页；分页参数 page（默认 1）、page_size（默认 20，最大 50） |
| 治理通知 | 治理删除在同一事务内完成软删除、审计与作者站内通知；通知含公告名称、处置结果、原因与公告引用（`announcement_id`）；正常发布、编辑、本人删除不产生通知 |

### 2.4 通知扩展（FR-08、FR-11，阶段 3 实施）

| 参数 | 取值 |
| --- | --- |
| 新增类型 | `announcement_admin_removed`（公告被管理员治理删除），接收人为公告作者 |
| 关联字段 | `notification.announcement_id` 可空外键（PROTECT）；公告关联与招聘/申请关联互斥：`announcement_id` 非空时 `recruitment_id`、`application_id` 必须为空；`application_id` 非空时 `recruitment_id` 必须非空 |
| 兼容 | 旧通知数据与字段保持兼容；邮件日志表保留，新业务事件不再创建 `EmailLog(PENDING)`，不再挂接派发回调 |

### 2.5 招聘与申请文本参数（FR-05、FR-07；阶段 4 实施校验适配）

| 参数 | 取值 |
| --- | --- |
| 招聘标题 `title` | 必填，去首尾空白后 1～100 字 |
| 需求描述 `description` | 必填，纯文本，去首尾空白后 1～5000 字 |
| 补充说明 `note` | 可选，去首尾空白后 ≤1000 字，空串归一为 null |
| 领域标签 | 候选值即 `seed_tags` 预设 19 项：计算机、软件工程、人工智能、电子信息、自动化与控制、机械、土木建筑、设计创意、交通运输、环境科学、材料、数学统计、经济管理、医学生命、人文社科、外语、艺术传媒、创新创业、其他；发布时必填、非空、不重复，每项须为启用标签 |
| 计划招募人数 | 正整数或正整数闭区间，`1 <= min <= max <= 200`；容量判断统一使用上界。**实施状态：** 上限 200 于阶段 4 落地，当前代码仍限制 50 |
