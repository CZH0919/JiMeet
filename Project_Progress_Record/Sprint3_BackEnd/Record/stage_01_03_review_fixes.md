## 修正结果

| 范围 | 已交付行为 |
| --- | --- |
| 注册与登录 | 新邮箱验码后取得一次性建号资格。已有账号仅在原会话验码成功后提示登录，不签发资格；并发注册只创建一个账号。密码与验证码登录统一校验完整同济邮箱域名、JSON、CSRF 和禁止缓存的响应头。两种发码入口使用相同的邮件故障提示。 |
| 公告权限与审核 | 普通用户投稿，管理员直接发布。Django 公告后台只读，不能单条或批量删除；用户后台不能更改业务管理员标记。审核领取固定 15 分钟，同一人重试不续期；交回、通过、驳回均校验当前领取人、批次和期限。 |
| 投稿通知 | 通过、驳回结果对投稿人可见。本人删除与治理删除分别通知发布人、投稿人，同一人只收一条。通知列表、未读数、单条和全部已读采用同一可见范围。 |
| 招聘与申请 | 新写入仅接受竞赛组队和校内活动。历史实习保留原始类型，对外统一显示为校内活动。公开列表和本人列表依次展示进行中、满员、关闭，组内按发布时间和编号倒序。招聘新增可选补充说明，与申请说明独立。 |

## 前端对接与迁移

- 注册示例已补齐 `role`、`password_confirm`。审核页保存领取响应的 `claim_id`、`claimed_until`，后续交回、通过或驳回传回原批次；收到 `SUBMISSION_LOCKED` 时刷新待审池。本人投稿、待审池和审核动作的响应字段见[接口正文第 8.2 节](../../../backend/design_file/api.md#82-投稿与审核)。
- 招聘表单和筛选现有的第三类“实验室实习”需由前端调整。活动筛选包含历史实习，旧筛选值 `internship` 仍可查询历史记录。招聘详情的 `note` 最多 1000 字，PATCH 省略时保留，传空可清除。见[招聘接口](../../../backend/design_file/api.md#5-招募接口)。
- 增量迁移为 `accounts.0005`、`announcements.0003` 和 `recruitments.0004`。从早于 `accounts.0004` 的版本升级，之前尚未核验的验证码须重发；从 `0004` 升到 `0005` 时，已核验但尚未使用的旧注册资格须重新发码核验，已注册账号和有效待验码保留。升级前仍有效的审核领取可由原领取人补取批次，保留原截止时间；旧招聘的补充说明默认为空。
