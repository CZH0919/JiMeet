# Sprint 3 前端对接说明

后端分支 `backend-sprint3`，运行支持实现提交 `ad339a6`。以[接口正文](../../../backend/design_file/api.md)为唯一契约。页面统一请求同源 `/api/v1`；路径无末尾斜杠。写请求携带会话 Cookie 和当前 `X-CSRFToken`，登录或建号后重新获取令牌。

| 页面 | 接入要点 |
| --- | --- |
| 注册、登录与本人资料 | 注册在同一会话依次发码、验码、建号。按 `account_exists` 决定是否进入密码设置页。已有账号可凭密码或登录验证码登录，验证码绑定用途及会话，有效期 5 分钟。注销须提交 `{"confirm":true}`，成功后清空本人缓存。见[账号接口](../../../backend/design_file/api.md#4-基础与账号接口)。 |
| 公告首页与审核 | 普通用户投稿或查看本人结果，管理员直接发布或从待审池领取。交回、通过或驳回均携带领取返回的 `claim_id`，处理 409 时刷新稿件状态。移除公告编辑入口；本人删除和治理删除按返回权限展示。见[投稿与审核](../../../backend/design_file/api.md#82-投稿与审核)。 |
| 招聘与申请 | 新发布仅支持竞赛组队、校内活动。招聘补充说明与申请说明分别保存。上传使用 multipart，允许 PDF、DOC、DOCX，最多 10 MiB。按服务端权限控制下载；发布者仅可读未删除招聘的处理中、已接受申请简历，到期记录从列表移除。见[招募接口](../../../backend/design_file/api.md#5-招募接口)、[申请与简历](../../../backend/design_file/api.md#6-申请与私有简历接口)。 |
| 对方主页与聊天 | 将 `src/data/index.ts` 中的演示聊天仓储替换为 HTTP 实现。首次联系传 `recruitment_id` 或 `application_id`；已有会话可直接打开。历史每页最多 50 条，使用 `before_id` 回翻，仅回执实际显示的对方消息编号。将 `uid/nickname`、`content` 对应到页面用户标识、展示名与正文；对方已注销时隐藏联系入口。见[聊天调用顺序](../../../backend/design_file/api.md#103-前端调用顺序)。 |
| 通知与未读 | 业务通知数和聊天未读数分别获取。通知标记已读、申请修改已阅、聊天回执各有独立入口。通知保留事件发生时的描述，详情及可用操作以当前接口返回值为准。见[通知接口](../../../backend/design_file/api.md#7-通知接口)。 |

**页面验收顺序**　用普通用户完成注册和投稿，由管理员领取并发布。用两个普通账号完成发布招聘、上传简历、处理申请和查看通知，再从业务来源联系对方、发送消息并确认已读。最后核对失去简历权限、账号注销后的回退，以及会话失效、页面刷新和移动端交互。

后端验证范围见[最终交付记录](stage_06_delivery.md)。服务启动、增量迁移、调度与故障反馈入口见[运行手册](../../../backend/deploy/README.md)。
