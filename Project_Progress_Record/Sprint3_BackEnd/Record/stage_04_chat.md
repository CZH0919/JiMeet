# Sprint 3 后端阶段 4　对方主页与站内聊天

2026-11-23，czh 完成[开发计划阶段 4](../Plan/sprint3_backend_plan.md)。分支为 `backend-sprint3`，开发基线为 `6a3cf4e`，实现提交为 `4434ab9`。对应[需求 3.1](../../../file/tasks/软件需求规格说明3.1.md) 的 FR-02、FR-10、FR-11。

## 交付内容

| 范围 | 完成情况 |
| --- | --- |
| 对方主页与会话 | 从公开招聘联系发布者，或由发布者通过本人收到的申请联系申请人。主页仅返回公开编号、昵称、师生身份和聊天入口。已有会话可直接续聊，同一对用户并发发起也只生成一个会话。 |
| 消息与未读 | 仅双方可发送和读取纯文本及 Emoji，支持离线收信、历史分页、会话摘要及未读计数。已读回执仅更新实际展示的对方消息，重复回执或同时到达的新消息均得到正确处理。管理员没有额外读取权限。 |
| 发送与留存 | 单条最多 500 个 Unicode 码点，每个发送者跨会话每滚动 60 秒最多发送 50 条，超限后暂停 60 秒。消息按上海本地发送时间保留六个自然月，到期即从历史、摘要和未读数中移除。 |

## 验证结果

- 服务器 PostgreSQL 隔离环境中，针对性回归 **44/44**、全量共享回归 **383/383** 通过，含本阶段新增的 19 项用例。覆盖 500/501 字符、50/51 条发送、双向并发建会话、读写并发、跨会话权限、月末与闰年到期、清理重跑和历史数据迁移。
- 另用三个独立会话完成真实 HTTP 验收，走通两种合法联系来源、离线收信、未读数、已读回执和回复，验证第三人访问返回 404。Django 系统检查和迁移差异检查通过。

## 对接与运行

- 新增 7 个方法与路径组合，请求、响应及调用顺序见[接口文档第 10 章](../../../backend/design_file/api.md#10-对方主页与站内聊天)。前端替换演示聊天仓储时，首次联系需传来源编号，按页加载消息（每页最多 50 条），并提交已展示消息的回执。浏览器交互由前端适配后验收。
- 增量迁移 `chat.0002_chat_delivery` 为已有及新消息计算到期时刻，增加发送暂停记录和索引。管理命令 `run_purge_chat_messages` 分批删除到期消息并保留会话，生产定时调度按阶段 6 交付。
