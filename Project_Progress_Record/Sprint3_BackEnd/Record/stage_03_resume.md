# Sprint3 后端阶段 3 记录：招聘、申请与简历权限

日期：2026-11-23｜分工：zf｜执行依据：[Sprint3 后端开发计划](../Plan/sprint3_backend_plan.md) 阶段 3、[需求 3.1](../../../file/tasks/软件需求规格说明3.1.md) FR-02～FR-08、FR-11｜状态：已完成

## 1. 范围

收紧简历访问权限（发布者对已拒绝、已撤回、已失效申请禁读预览与下载）；统一文件权限与申请记录/补充说明可见性的判断口径；复核招聘截止修改、人数区间、撤回重投、未读标记、删除失效、七天窗口、满员优先与通知范围等既有规则并回归。

## 2. 核心修改

### 2.1 简历权限收紧（`backend/apps/applications/policies.py`）

- `resolve_application_access` 的 `can_download_resume` 收紧为：申请人始终可下载本人保留文件；**发布者仅可预览或下载“招聘未删除且申请为 processing/accepted”的简历**，已拒绝、已撤回、已失效一律禁读（下载 403、详情不返回简历元数据）。
- 文件权限与申请记录、补充说明可见性分别判断（rejected 的补充说明对发布者仍可见）；管理员无任何额外读取权。同一权限出口覆盖列表、详情 `can_download_resume`、简历元数据与 `GET /applications/{id}/resume` 文件流（`files/services.download_resume` 复核同一规则）。
- 保留首次上传隐私确认、私有存储、PDF/DOC/DOCX 与 10 MiB 限额不变。

### 2.2 规则复核（回归确认，无代码改动）

- 两类招聘、关键词与标签筛选、发布时间倒序、关闭项后置、本人已投状态、个人主页发布/投递/收到申请入口。
- 进行中招聘可提前或延后截止时间（新时间须晚于修改时刻且不晚于此后一个日历年）；人数下限仅展示、上限决定满员、不得调低至已接受人数以下。
- 撤回后可重新投递（新记录）、申请修改的未读标记与通知、招聘软删除的失效与人数归零、关闭后七天处理窗口、满员优先并自动拒绝剩余处理中申请、本人删除与治理删除分入口（治理含原因并通知发布者）、招聘变更通知仅覆盖相关处理中/已接受申请人。

### 2.3 接口文档（`backend/design_file/api.md`）

6.1 可见性矩阵按新规则重写（发布者 rejected 行单列：简历元数据与文件“不返回，预览与下载均禁用”），补充“同一规则覆盖列表/详情/文件流”的口径说明。
