## 2. 前端对接要点

- **唯一接口正文：** `backend/design_file/api.md`。统一前缀 `/api/v1`，无末尾斜杠；正常配置可用 39 个方法/路径，启用开发登录时增加 1 个，另有 2 个 SSO 501 预留。
- 使用邮箱密码注册登录；写请求携带当前 CSRF 令牌及会话 Cookie。开发登录只用于隔离调试，不能作为正式注册登录验收方式。
- 根据响应的 `permissions` 展示操作；本人删除与管理员治理删除使用不同入口，治理原因必填。管理员身份不增加申请内容或简历读取权限。
- 简历采用 multipart 上传，非空、最多 10 MiB；撤回或招聘删除后，申请人可下载保留文件，发布者禁读对应文件。列表不暴露简历存储路径。
- 申请详情读取不清除修改标记；展示后用 `seen_updated_at` 确认已阅。通知已读另行操作，二者互不代替。
- 通知的 `target_is_deleted` 表达关联招聘或公告当前已删除；正文保留历史事件语义，当前申请状态与下载权限由申请接口提供。公告的 `recruitment_available` 不表示招聘仍可投递。
- `email_notify_enabled` 为兼容字段，不代表可用的邮件功能；前端页面适配和浏览器测试由前端团队负责。

## 3. 运行与迁移

依赖与配置入口分别为 `backend/requirements/base.txt`、`backend/.env.example`；运行时从进程环境变量读取配置，不自动加载 `.env`。Python 要求 3.12+，PostgreSQL 要求 15+；私有文件目录不映射为公开静态资源。

在目标环境执行 `python manage.py migrate` 应用全部待执行迁移，以下变更需纳入接入检查：

| 迁移 | 作用与兼容边界 |
| --- | --- |
| `accounts.0002_authfailure` | 增加注册/登录失败计数，保存摘要键，不保存明文认证凭据。 |
| `notifications.0002_notification_announcement_and_more` | 增加公告关联及目标互斥/完整性约束，旧通知保持兼容。 |
| `recruitments.0003_stage4_rules` | 幂等归零历史已删除招聘的接受人数，保留业务状态和时间；不推断恢复未知旧统计。 |
| `applications.0002_stage4_rules` | 增加申请状态历史及约束，不补造无法证实的历史事件。 |

`seed_tags` 提供标签初始化；`run_sync_recruitments` 需由运行环境独立调用或调度，完成到期、七天及满员补执行。账号管理使用 `grant_admin`、`revoke_admin`、`init_password` 受控命令。测试专用密码哈希不得用于正常服务。
