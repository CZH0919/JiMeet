# Sprint2 后端阶段 5：通知与个人申请状态一致性

日期：2026-11-14｜负责人：czh｜开发基线：`0ceafce`｜工作分支：`backend_sprint2`｜状态：完成

依据：[Sprint2 后端开发规划](../Plan/sprint2_backend_plan.md)阶段 5。

## 1. 核心完成情况

- **长期通知：** 移除通知生成、列表、未读数及单条/全部已读中的固定 180 天截断，统一接收人与关联权限；迟到状态补执行仍生成一次必要通知。保留旧数据，不重写历史正文或补造已丢失事件。
- **接收与关联：** 按事件矩阵校验申请人、招聘发布者及公告作者，治理通知要求原因；关联不符的旧记录不进入读取或已读范围。管理员无额外私有读取权，公告作者撤权后仍可读取本人治理通知。
- **删除与状态：** 通知新增 `target_is_deleted`，动态表达关联招聘或公告的删除状态；历史通知保留事件语义，当前申请状态与权限由申请接口提供。删除提示不恢复公开详情或发布者简历权限。
- **去重与事务：** 保持状态锁、重复动作拒绝和业务事务回滚；相同招聘内容/标签集合、相同申请说明且未上传新文件的更新不生成新版本、通知或未读标记。新文件提交仍为一次更新。
- **个人申请：** 核验五种申请状态、历史与删除提示、首次决定时间、本人下载及发布者私有标记。通知已读与申请修改的已阅确认独立，列表读取不自动清除任一标记。
- **通知内容：** 主动拒绝、满员拒绝和处理期届满分别说明原因，招聘删除通知明确申请失效；全部业务事件继续只创建站内通知。

## 2. 对接与兼容

- 接口正文：`backend/design_file/api.md`；方法/路径数量不变，新增响应字段 `target_is_deleted`，原通知字段保留。无关联旧通知该字段为 false；客户端仍须通过目标接口查询当前状态和权限。
- 通知接收矩阵、无变化更新规则及历史消息语义已写入接口文档，并同步数据库设计与需求附文。
- 无新增数据库迁移；原有状态历史、通知关联约束与审计机制继续使用。
