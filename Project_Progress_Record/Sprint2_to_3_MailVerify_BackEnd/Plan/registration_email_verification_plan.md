## 2. 拟定接口契约

以下路径均以 `/api/v1` 为前缀。客户端先调用 `GET /auth/csrf`。首次申请验证码时建立匿名会话，后续请求携带同一会话的 Cookie。三个写接口均校验 CSRF。

| 步骤 | 接口 | 行为与结果 |
| --- | --- | --- |
| 申请验证码 | `POST /auth/register/send-code` | 提交邮箱，向可注册的同济地址发送验证码。对格式合法的已注册邮箱返回相同的受理提示，避免暴露账号是否存在。响应不回传验证码。 |
| 验证邮箱 | `POST /auth/register/verify-code` | 提交邮箱与验证码。通过后消耗该码，在服务端记录绑定当前匿名会话、规范化邮箱和注册用途的短时注册资格，此时尚未建号。 |
| 完成注册 | `POST /auth/register` | 沿用邮箱、密码、姓名及可选资料字段。服务端校验注册资格与密码，在同一数据库事务内创建普通账号并消费资格。成功后沿用 `201`、本人资料及会话建立行为，前端重新获取 CSRF 令牌。 |

## 3. 开发阶段

| 阶段 | 核心工作 | 完成标准 |
| --- | --- | --- |
| 1. 契约与数据设计 | 明确请求字段、响应、重发间隔和资格失效后的处理方式，供前端对接。设计 PostgreSQL 验证记录、过期清理和增量迁移。 | 明确验证码和注册资格的有效期、状态转换及建号时点。新规则同步至 FR-01、需求附文和验收用例。 |
| 2. 发码与投递 | 使用安全随机码，将其绑定邮箱、会话和注册用途，仅保存带服务端密钥的摘要。按邮箱、可信来源 IP 和全局额度在数据库中原子预占发送次数，提交事务后通过 Django 和同济 SMTP 加密投递。 | 同一注册会话成功重发后仅最新码有效。投递失败不激活当次验证码，超限返回 `429`，邮件服务不可用返回 `503`。并发请求及迟到的投递结果不能使旧码重新生效。 |
| 3. 核验与建号 | 实现限次核验、资格过期和一次性消费，复用原密码策略、邮箱唯一约束和会话机制。保留既有账号的密码、权限及隐私确认状态。 | 跳过核验、跨邮箱或跨会话提交、重放均无法建号。密码不合规可在资格有效期内改正，并发完成注册最多创建一个账号。 |
| 4. 后端验收与交接 | 在服务器验证 HTTP 接口、数据库和会话，更新 API 正文、数据库设计及调用示例。向前端交付三步注册顺序、Cookie 和 CSRF 要求及错误处理约定。 | 后端以接口主流程、边界回归通过和文档与实现一致为交付标准。 |

建议初值为 6 位数字验证码、10 分钟有效、60 秒后可重发、每码最多输错 5 次，核验通过后的注册资格有效期为 10 分钟。上述值及各层发送额度在阶段 1 定稿，并纳入边界测试。

## 4. 验收分工与数据隔离

- **后端主流程**在独立回归库使用合成邮箱和保留 Cookie 的 HTTP 客户端。调用发码接口，由测试程序从隔离邮件收件箱读取本次实际生成的验证码，再验码、设置密码并注册。断言验码后仍无账号，注册成功仅新增一个普通账号，`GET /me` 可访问，退出后可凭新密码再次登录。接口测试无需人工收码。
- **边界回归**覆盖非法域名、重复邮箱、CSRF 拒绝、过期、输错、重发、跨会话、并发及 SMTP 失败。验证既有账号的登录和权限，注册成功后首次申请仍须确认隐私条款。
- **数据隔离**要求在迁移或启动测试实例前核对实际数据库名及连接角色。自动化回归使用独立测试库，后续网页联调的前端代理只指向连接开发场景库的实例。部署只交付代码与结构迁移，测试账号、验证码和会话不导入生产库。
- **前端后续验收**由前端同学为 `/login` 的注册视图接入发码、验码及设置密码，随后使用测试者本人可收信的同济邮箱完成浏览器注册，单独记录实收、页面反馈和登录结果。[现有注册视图](../../../src/pages/LoginPage.tsx)
- **记录要求**区分既有 SMTP 实投证据、后端接口测试和后续浏览器验收。日志及团队记录保留结果和错误类别，不记录个人邮箱地址、验证码、密码、注册凭据或会话标识。
